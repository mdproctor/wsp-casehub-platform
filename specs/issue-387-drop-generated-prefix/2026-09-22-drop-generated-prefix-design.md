# Drop Generated Prefix and .generated. Package from APT Output — Design Spec

**Issue:** casehubio/platform#387
**Date:** 2026-09-22
**Status:** Draft

## Summary

The `GraphQLResolverProcessor` APT currently generates REST resources and GraphQL
resolvers with a `Generated` prefix and in hardcoded `.generated.` packages:

```
io.casehub.platform.rest.generated.GeneratedAclResource
io.casehub.platform.graphql.generated.GeneratedAclResolver
```

This leaks implementation detail into class names, stack traces, and logs. It also
prevents generated classes from being drop-in replacements for hand-written resources,
forcing import/injection refactoring during migration.

This spec changes the output to clean names in SPI-derived packages:

```
io.casehub.platform.rest.acl.AclResource
io.casehub.platform.graphql.acl.AclResolver
```

The `graphql-spring-generator` Maven plugin also has a hardcoded `.generated.`
package and is updated for consistency.

## Changes

### 1. Drop `Generated` prefix from class names (D1)

**GraphQLResolverProcessor — two lines:**

```java
// generateResolverSource (line 694)
// Before:
String className = "Generated" + toPascalCase(domain) + "Resolver";
// After:
String className = toPascalCase(domain) + "Resolver";

// generateRestResourceSource (line 788)
// Before:
String className = "Generated" + toPascalCase(domain) + "Resource";
// After:
String className = toPascalCase(domain) + "Resource";
```

The class name validation guard (`SourceVersion.isIdentifier`) stays — it validates
the result after `toPascalCase`, regardless of prefix.

### 2. SPI-derived output package with APT override (D2, D3)

**New APT options:**

Add `restPackage` and `graphqlPackage` to `getSupportedOptions()`:

```java
@Override
public Set<String> getSupportedOptions() {
    return Set.of("generateGraphQL", "generateRest", "domainFilter",
                   "restPackage", "graphqlPackage");
}
```

**New method — `deriveOutputPackage`:**

```java
static String deriveOutputPackage(String spiPackage, String channel) {
    // channel is "rest" or "graphql"
    int apiIdx = spiPackage.indexOf(".api.");
    if (apiIdx >= 0) {
        return spiPackage.substring(0, apiIdx) + "." + channel
               + spiPackage.substring(apiIdx + 4);
    }
    if (spiPackage.endsWith(".api")) {
        return spiPackage.substring(0, spiPackage.length() - 4) + "." + channel;
    }
    return spiPackage + "." + channel;
}
```

Examples:
| SPI Package | Channel | Output Package |
|---|---|---|
| `io.casehub.platform.api.acl` | `rest` | `io.casehub.platform.rest.acl` |
| `io.casehub.platform.api.acl` | `graphql` | `io.casehub.platform.graphql.acl` |
| `io.casehub.chat.api` | `rest` | `io.casehub.chat.rest` |
| `io.casehub.chat.api` | `graphql` | `io.casehub.chat.graphql` |
| `io.casehub.something` | `rest` | `io.casehub.something.rest` |

**Resolution order in `generateRestResourceSource` and `generateResolverSource`:**

```java
String restPkgOverride = processingEnv.getOptions().get("restPackage");
String packageName = restPkgOverride != null
    ? restPkgOverride
    : deriveOutputPackage(spiPackage(ops), "rest");
```

Where `spiPackage(ops)` extracts the package from the first operation's
`declaringClassFqcn`. Since all operations in a `DomainOperations` come from the
same `@McpDomain`-annotated class, the package is consistent.

**New helper:**

```java
private static String spiPackage(DomainOperations ops) {
    String fqcn = ops.operations.get(0).declaringClassFqcn();
    int lastDot = fqcn.lastIndexOf('.');
    return lastDot > 0 ? fqcn.substring(0, lastDot) : "";
}
```

### 3. Remove `.generated.` package check from enforceNoHandWrittenRest

**Current (line 169):**
```java
if (name.contains(".generated.")) continue;
```

**Remove this line.** Generated classes carry `@McpDomain`, which the existing
`hasMcpDomain` check (line 176) already handles. The `.generated.` check was a
redundant short-circuit that is no longer applicable.

### 4. Update graphql-spring-generator output package (D4)

The `graphql-spring-generator` Maven plugin currently outputs all classes to a
hardcoded `io.casehub.platform.graphql.spring.generated` package. Apply the same
derivation rule, then append `.spring`:

| SPI Package | Spring GraphQL Output |
|---|---|
| `io.casehub.platform.api.acl` | `io.casehub.platform.graphql.acl.spring` |
| `io.casehub.chat.api` | `io.casehub.chat.graphql.spring` |

And for Spring REST controllers generated by the same plugin:

| SPI Package | Spring REST Output |
|---|---|
| `io.casehub.platform.api.acl` | `io.casehub.platform.rest.acl.spring` |
| `io.casehub.chat.api` | `io.casehub.chat.rest.spring` |

The derivation logic is duplicated from the APT (both are ~10 lines of string
manipulation — not worth a shared dependency given the APT's minimal-dependency
constraint per spec #299).

### 5. Update verify mojos

Both the `graphql-spring-generator` verify mojo and any drift-detection rules that
reference `.generated.` packages need updating to expect the new output packages.
The verify mojos detect drift by comparing generated output against expected targets —
the expected package names must match the new derivation.

## Migration Path

### Platform (this PR)

1. Change the generator output — new class names and packages
2. Update all 21 compile-testing test assertions to expect new names
3. Remove the `.generated.` check from `enforceNoHandWrittenRest`
4. Build passes — generated classes in platform modules get new names on next `mvn install`

### Consumer repos (follow-up, not this PR)

After this PR lands and platform is published:
1. Consumer `mvn compile` automatically gets new generated class names
2. If consumers have explicit imports/references to `GeneratedXyz` or `.generated.`
   packages, compilation fails — that is the intended signal to clean up
3. Hand-written skip detection prevents naming conflicts during transition —
   if a hand-written `AclResource` exists with `@McpDomain`, the generator skips it
4. #388 (extract inner records) and #389 (service injection) can be done per-repo
   after the generated classes have clean names

### What consumers need to do

- **If using `-AdomainFilter` only:** Nothing. The generated classes change names
  automatically. Old `GeneratedXyz` references (if any) need updating.
- **If explicitly importing generated classes:** Update imports from
  `io.casehub.platform.rest.generated.GeneratedXyzResource` to the new derived
  package and class name.
- **If hand-written REST resources co-exist:** Delete the old hand-written resource.
  The generator now produces a drop-in replacement with the same name.
