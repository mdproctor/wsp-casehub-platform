# NearMiss Guided Rejection

**Issue:** #973
**Parent:** #959 (unified template registry)
**Branch:** issue-973-nearmiss-guided-rejection

## Problem

Both `InMemoryTemplateRegistry` and `NlpTemplateRegistry` return only `Matched` or `Unmatched`. The `TemplateMatch.NearMiss` variant exists in the type system but nothing produces it. When a message is structurally close to a template but doesn't quite match, the agent gets a bare rejection with no guidance on how to rephrase.

## Design

### NearMiss Production Rule

`NlpTemplateRegistry.matchInNamespace()` produces `NearMiss` when:

1. Regex tier returned `Unmatched` (no exact match)
2. Keyword affinity passed the affinity threshold (structural matching was attempted)
3. `StructuralMatcher.match()` returned a partial score > 0 but below `scoreThreshold` (default 0.5)

This requires structural evidence — not just keyword overlap. If the structural matcher scored 0 (no elements matched), the result stays `Unmatched`.

The best-scoring near-miss candidate (highest partial score) is selected. Its template pattern is formatted into `suggestedFormat` using the same `${varName}` → `[varName]` substitution as the existing `TemplateMatchingFilter.formatSuggestion()`.

### Where NearMiss Is Not Produced

- **`InMemoryTemplateRegistry`** (regex tier only) — regex matching is binary (match or not). No partial scoring is possible without the structural matcher. Stays `Matched` or `Unmatched`.
- **Global `match(String input)`** — if any namespace produces a `Matched`, NearMiss from other namespaces is suppressed. NearMiss only surfaces when no namespace matched.

### Format Suggestion

`suggestedFormat` is generated by stripping optional-segment brackets and replacing `${varName}` with `[varName]`:

```
Template: "I ${decision} this ${subject}[ because ${rationale}]"
Format:   "I [decision] this [subject] because [rationale]"
```

This logic is extracted into a shared `TemplateFormatHelper` utility in `template-registry-api` (currently duplicated in `TemplateMatchingFilter.formatSuggestion()` in yaml-step-runtime).

### Enforcement Pipeline (qhorus issue)

A linked qhorus issue will wire NearMiss guidance through the enforcement pipeline:

- When a governance playbook step returns `NearMiss`, the step output includes `suggestedFormat` and `suggestedTemplate` in the result map
- `PlaybookProtocolOutput.parse()` can pass this through to `DispatchAdvisory.evidence`
- The agent receives: `evidence: { "suggestedFormat": "I [decision] this [subject]", "suggestedTemplate": "vote" }`

No new types needed in qhorus — the existing `evidence` map on `DispatchAdvisory` carries the data.

### Module Changes

| Module | Change |
|--------|--------|
| `template-registry-api` | Add `TemplateFormatHelper` (extracted format suggestion logic) |
| `template-registry` | `NlpTemplateRegistry.matchInNamespace()` produces `NearMiss` on partial structural match |
| `template-registry` | `NlpTemplateRegistry.match(String input)` — cross-namespace NearMiss tracking (best near-miss when no namespace matched) |

## Testing

1. **TemplateFormatHelper** — format suggestion from template patterns (existing test cases from TemplateMatchingFilter)
2. **NlpTemplateRegistry.match() NearMiss** — tense variation that partially matches but scores below threshold → NearMiss with suggestedFormat
3. **NlpTemplateRegistry.match() Unmatched stays Unmatched** — completely unrelated input (zero structural score) → Unmatched, not NearMiss
4. **NlpTemplateRegistry.match() Matched suppresses NearMiss** — exact match in one namespace, partial in another → Matched wins
5. **Global match NearMiss** — cross-namespace: no match anywhere but one namespace has a near-miss → NearMiss returned
