**1. Batch 6: callback-spring Module.**

New module `callback-spring` — Spring equivalent of the CDI `@Decorator` pattern generated by `callback-generator`. Runtime approach using `BeanPostProcessor` + JDK dynamic proxies (no build-time generator needed):

- `CallbackSpringAutoConfiguration` — `@AutoConfiguration`, produces `CallbackInvoker` bean (equivalent of Quarkus `CallbackBeans`), registers static `BeanPostProcessor` factory
- `CallbackDecoratorBeanPostProcessor` — scans each bean for `@CallbackEligible` interfaces, wraps matching beans with JDK proxies. Uses `ObjectProvider<>` for lazy resolution of `CallbackRegistry`/`CallbackInvoker`/`CurrentPrincipal`
- `CallbackInvocationHandler` — proxy handler: checks `CallbackRegistry.findBySpi()` per method call, routes through `CallbackInvoker` when registrations exist, delegates to real bean otherwise. Respects `fanOut` (iterate all) vs single-impl (first only)
- 5 passing tests (wrapping, delegation, fanOut, non-eligible bypass, kebab-case)
